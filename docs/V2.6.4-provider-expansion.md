## Pipeline

One official HTML page per retailer -> bounded fetch (6 MB, 15-second attempt)
-> htmlparser2 DOM -> independent parser candidates -> strict normalization
-> validation -> retailer-scoped dedupe -> up to 40 candidates per provider
-> global ranked selection -> existing eBay/Decision Intelligence pipeline.

Target: embedded JSON -> visible HTML cards -> JSON-LD.
Walmart: Next data -> relocated embedded JSON -> cards -> JSON-LD.
Kohl's: embedded JSON -> cards -> JSON-LD. Home Depot retains Apollo state.
Scripts are JSON parsed, never executed. Parser exceptions do not stop fallbacks.
Malformed JSON is ignored; missing public records is unavailable, not an empty
market. Explicit Walmart empty itemStacks remains a legitimate empty response.

403, 429 and challenge documents stop without retry. Other fetch failures allow
one bounded retry. Success cache: 10 minutes; failure/unavailable cache: 1 minute,
per isolate only. No distributed retailer cooldown is claimed. Robots/terms and
permitted access should be reviewed before scaling or commercial deployment;
public accessibility alone does not establish legal permission for every use.

## Price and Identity

Require title, exact current price, retailer-owned HTTPS product URL, and an
explicit higher reference price or product-level clearance evidence. Reject
ranges, AggregateOffer price ranges, non-USD offers, multiple-variant offers,
conditional-only pricing and unscoped HTML containers containing multiple URLs.
Unconditional price stays separate from coupon/member prices. Their discounts
are not automatically applied. HTML cards with ambiguous coupon/member conditions
are rejected rather than guessing. Unknown original price means null discount.

Fields are additive: currentPrice/salePrice, referencePrice/regularPrice,
referencePriceType, couponPrice, memberPrice, dealType, parserSource,
sourceConfidence, dataQuality, category, rating, reviewCount and popularity.
No missing brand/model/category/store stock is invented. Quality labels measure
field completeness/parser provenance, not accuracy probability or resale value.

Dedupe precedence within retailer: UPC/GTIN, SKU, product ID, tracking-normalized
URL, brand+model, normalized title. Variant query parameters are preserved.
Cross-retailer deals remain separate. Historical stableDealKey is unchanged.

## Budget and Ranking

PreScore (0-100) allocates analysis, not BUY confidence: discount up to 30 points,
supplied brand 10, model/global ID 20, retailer ID 5, suitable category 15,
$15-$300 price 10, clearance 5, high field completeness 5; bulky indicators -20.
No brand reputation or expected profit is fabricated. Categories are advisory,
not hard exclusions. Out-of-stock products are excluded.

Scheduled candidates require >=30% observed discount OR explicit clearance.
Manual candidates need not meet that threshold. Both use a global descending
PreScore list, deterministic ties, max 8 total and max 4 per retailer. No forced
diversity quota consumes calls on weak records. Unused capacity is allowed.

Limit also uses floor(min(remaining daily, remaining minute)/2). Existing D1
atomic reservations are the final authority under concurrency. Cooldown selects
zero candidates. Product > Manual > Scheduled quotas remain unchanged. Eight is
a ceiling, not a promise: default minute quotas often limit Manual to 7 and
Scheduled to 5 on an otherwise empty minute. Cache hits can make this conservative.
`budgetSkipped` remains for compatibility but now counts all eligible candidates
deferred by selection limits; `candidateSelection` exposes explicit totals.

success/unavailable/error counters and last success/failure. This is NOT the
globally durable eBay health ledger. Scheduled provider summaries persist these
observations in the existing scan_runs.provider_summary; no 0005 migration.

UI provider list, field capabilities and retailer filter come from API responses.
Price/original/model support reflects the current sample, not retailer guarantees.
Empty old fields display unavailable/N/A. Decision Engine and authentication are
unchanged. No notifications, retailer login or external paid service added.

Before production: `npm ci`; restore Cloudflare auth; confirm migrations through
0004 already applied; run authenticated edge fetch verification before adopting
Target/Kohl's; deploy; verify Product/Deal, D1 history and Scheduled budget cap.
No new Secrets/Variables are needed. V2.7 notifications remain gated on production
provider/Decision Intelligence regression and freshness/dedupe/opt-in checks.
